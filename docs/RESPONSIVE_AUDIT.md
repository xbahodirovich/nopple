# Nopple Responsive Audit (`pro-redesign`)

Diagnostic audit only — no application code was modified.
Audited with [audit-responsive.mjs](file:///Users/malkinpi/Projects/nopple/scripts/audit-responsive.mjs) across **Chromium (1.63)** and **WebKit (26.6)** on **14 unique viewports** per page (84 combinations per browser, 168 total):

- **Phone portrait & landscape:** `320x568` / `568x320`, `360x740` / `740x360`, `390x844` / `844x390`, `412x915` / `915x412`
- **Tablet portrait & landscape:** `768x1024` / `1024x768`, `820x1180` / `1180x820`
- **Desktop:** `1280x800`, `1440x900`

*(Note: `768x1024` in landscape is `1024x768`, and `1024x768` in portrait is `768x1024`, so those pairs share one run each without duplication.)*

## Baseline Checks Passing Across All 168 Runs

- **Viewport `<meta>` tag:** Present on all pages (`width=device-width,initial-scale=1` on `/`, `/editor`, `/homes`, `/share`; `width=device-width, initial-scale=1.0` on `/advanced` and `brief-flow`).
- **Document-level horizontal overflow:** `0` occurrences (`document.documentElement.scrollWidth <= innerWidth` across all 168 runs in Chromium and WebKit).
- **Runtime errors:** `0` uncaught `pageerror` events in Chromium and WebKit.
- **3D canvas rotation (`setViewportSize` swap):** All WebGL pages (`/editor`, `/advanced`, `/share`) resize both CSS box and drawing buffer on orientation change — except where container layout crushes the viewport height prior to or after rotation (see `/advanced` and `/share` issues below).
